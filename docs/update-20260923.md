## Analysis

### 1. `frontend/sw.js` — non-`http(s)` requests were being cached

The `fetch` listener ran every request through one of three branches, and two of
them write to the cache. A browser extension on the display machine was issuing
`chrome-extension://` fetches, which the service worker intercepts like any
other; `cache.put` **rejects** on a scheme the Cache API does not support, which
rejects the `respondWith` promise and fails a request the page never made.

The fix is one guard as the first line of the handler:

```js
if (!e.request.url.startsWith('http')) return;
```

Returning *without* calling `respondWith` is the important part — it hands the
request back to the browser's default handling, which is the only correct answer
for a scheme we do not cache.

### 2. `frontend/js/display.js` + `display.css` — the cross-fade was not a cross-fade

The old slideshow had a single `<img id="promoImg">`. `showSlide()` added a
`.fade-out` class, then a `setTimeout(…, 1000)` hard-coded to match a `1s` CSS
transition swapped `src` and removed the class. Two consequences, both visible on
a large screen:

- the fade went **through the dark `#111` panel background** between every slide,
  rather than one image dissolving into the next;
- the new `src` only began decoding *as it became visible*, so the fade-in could
  reveal a partially decoded image.

Plus the timer and the CSS duration were two numbers in two files that had to
agree, with nothing to catch a change to one of them.

Now: two stacked `.promo-layer` images (`promoImgA` / `promoImgB`), both
`position:absolute; inset:0`, transitioning **`opacity` only** (1.2s), with
`.active` as the visible state. `showSlide()` preloads the incoming URL through a
throwaway `new Image()` and performs the class swap in its `onload` / `onerror`,
so the overlap happens between two fully decoded frames.

The old CSS-selector fallback rules (`img[src=""] ~ .display-promo-fallback` and
friends) are gone — with two layers those selectors cannot express the state. The
branding fallback is now JS-driven, and `clearPromoLayers()` is the single reset
path; previously two separate branches in `fetchSlides()` each cleared one `src`
by hand.

### 3. `frontend/display.html` + `display.css` — fullscreen image, overlaid orders

`.display-container` was a `grid-template-columns:2fr 1fr` split: photo on the
left, orders in a flat navy column on the right. On the foyer TV that spent a
third of the screen on at most 13 order numbers and cropped every photo to two
thirds width.

Now `.display-container` is `position:relative`, `.display-promo` sits at
`inset:0`, and `.display-orders` is absolutely positioned over the right 30%
(`min-width:380px`, `z-index:10`).

Because the orders now sit over an arbitrary photograph rather than a flat
background, readability is carried by a **horizontal scrim** on the panel
(transparent → `rgba(10,14,26,0.35)` at 18% → `rgba(10,14,26,0.92)`), plus
`backdrop-filter:blur(2px)` and `text-shadow` on the hero cards, compact items,
dividers and empty state. Hero-card fills went from opaque to
`rgba(6,95,70,0.85)` and their glow shadow from green to black, so the card reads
as sitting *on* the photo.

Portrait TV mounts (the `@media (orientation:portrait)` block) previously
restacked the grid 60%/40%. They now get the same overlay treatment as a bottom
strip: `inset:auto 0 0 0`, `height:42%`, scrim rotated to `to top`.

**Graceful degradation checked:** every blurred surface also carries an opaque-
enough `rgba` fill and, on the compact items, a `1px` border — so a TV browser
without `backdrop-filter` support loses the blur and keeps the contrast.

### Not part of this diff: a production data change

Three `DISPLAY_SLIDE#…/META` records in `rlc-cafe-settings` had aged out
(`expiryDate` in the past), leaving the display with nothing to show. Their
`expiryDate` was moved to `2026-12-31` earlier in the session with
`scripts/bump-slide-expiry.mjs`, **already run against production**. Recorded
here for the audit trail; there is nothing to re-run and nothing user-visible to
add to the changelog.

The script conforms to the `Data scripts` invariants: dry run by default, writes
only with `--apply`, prints a before/after diff, idempotent, region
`ap-southeast-5` hardcoded. It touches `expiryDate` only and its header says why
it must never touch `expiresAt` — the settings table's TTL fires on that
attribute, so a numeric value on a slide would have DynamoDB delete it silently.
That distinction is now also in the `db-schemas` skill, where it was missing.

## Open items

- **(a) `promoLayers` in `display.js:15` is dead.** Assigned at `:275` as
  `[promoImgA, promoImgB]` and never read — `showSlide()` picks the incoming
  layer by comparing against `activeLayer` directly. Left in place rather than
  edited during a release pass; it is two lines and should be deleted next time
  the file is open.
- **(b) A broken slide URL is activated rather than skipped.** `showSlide()`
  binds the same handler to `preload.onload` and `preload.onerror`, so a 404
  image still gets `src` set, `.active` added and the branding fallback hidden —
  a blank layer fades in over the previous slide. This is **not a regression**
  (the old timer-based swap set the broken `src` unconditionally too), and
  binding `onerror` is what stops a failed preload freezing the slideshow.
  Better: on `onerror`, leave the current layer active and advance to the next
  slide.
- **(c) The v1.77.0 palette deferral (af) still stands.** `display.css` keeps its
  own hand-written dark navy values (`#111`, `rgba(10,14,26,…)`, `#4ade80`) and
  is still not on the `style.css` token palette. This was a layout change, not a
  repaint; a dark variant remains an unreviewed design decision.
- **(d) Unrelated in-progress work was in the tree at release time and is NOT in
  this commit.** A separate "edit an existing display slide" feature appeared
  mid-pass — `backend/src/routes/admin.ts` (new `PUT /api/admin/display/slides/{id}`
  plus a shared `slideDateRejection()` validator), `backend/tests/admin-misc.test.ts`,
  and `frontend/js/admin-display.js` (an Edit button and `openSlideEditForm()`).
  All three were left **uncommitted and unstaged**, `frontend/js/admin-display.js`
  explicitly unstaged after `git add frontend` picked it up. Shipping that
  frontend without its backend is precisely the deploy asymmetry the release-flow
  skill warns about: the Edit button would call an endpoint that does not exist in
  production. It needs its own version (v1.81.0), its own changelog entry, a
  backend deploy **first**, and its own `api-reference` / `db-schemas` /
  `invariants` sync — `PUT .../slides/{id}` is a new endpoint, and the
  create/edit-parity validator is worth recording.
- **(e) The new overlay was verified as an approved mock and by static checks,
  not on the real TV.** Worth one look at the foyer screen on the next Sunday,
  in both orientations, to confirm the scrim reads well against the actual
  slides.
